# Игра без подключений

## Самый простой запуск

1. Скачайте **docs/index.html**. В GitHub откройте файл и нажмите **Download raw file** справа над исходным кодом (можно также скачать репозиторий через Code → Download ZIP).
2. Откройте сохранённый HTML-файл в обычном современном браузере. На экране сразу появится вводная игры.
3. Начните 30 минут и проходите задания. Установка приложений, Node.js, регистрация и настройка сервисов не нужны.

Это один самодостаточный файл: оформление, React, иконки, задания, подсказки и экспорт встроены внутрь. Игра не обращается к API, внешним шрифтам или CDN. Если на рабочем компьютере политика компании запрещает открывать локальные HTML-файлы, используйте опубликованную GitHub Pages версию либо разрешённый корпоративный статический сайт.

## Как играть

Семь основных заданий с вводной и итогом, восемь критериев и порог 2 «да», общий таймер 30 минут, подсказки ЦЭИ и итоговый план из реальных ответов. Все механики исходного сценария сохранены: маршрут, роли, чемпионы, затронутые группы/потери/возражения, коммуникации, две метрики принятия, технические риски, сопротивление, план Б и четыре этапа внедрения.

Можно проходить одному или обсуждать командой у одного экрана/через демонстрацию экрана. В левом меню доступны три независимых рабочих листа команд. Переименуйте команду и переключайтесь между листами. Таймер общий для всей локальной игры, его можно поставить на паузу. Он сохраняется при обновлении страницы и завершает отсчёт по сохранённому времени.

Доступны все задания без принудительной блокировки; к итоговому плану можно перейти в любой момент. Незавершённые разделы помечаются «Требует уточнения». Проверка правил объясняет ошибки и позволяет исправить ответ.

## Ответы и резервные копии

Ответы сохраняются в хранилище текущего браузера после каждого действия. Это локальное сохранение, **не совместная синхронизация разных устройств**. Серверная версия с полноценными ролями и синхронизацией остаётся в этом же репозитории.

Кнопка **«Сохранить резервную копию»** скачивает все листы и таймер в `workshop-backup.json`. **«Загрузить копию»** восстанавливает этот файл после явного подтверждения замены текущих листов. Проверка формата не позволяет загрузить повреждённые или неподходящие данные. Пустые названия команд восстанавливаются безопасно, без потери ответов.

Итоговый план отдельной команды можно скачать в Markdown, экспортировать ответы в JSON или распечатать/сохранить в PDF через браузер. JSON плана отдельной команды и резервная копия всех листов — разные файлы; для восстановления всей игры используйте `workshop-backup.json`.

В приватном режиме, при запрете localStorage или очистке данных браузера сохранение может быть недоступно/удалено. Игра показывает предупреждение; скачайте резервную копию до закрытия вкладки. Для локальных `file://` браузеры по-разному связывают сохранение с путём файла: переименование/перемещение файла может создать другое хранилище. Сохранённый JSON переносит ответы независимо от пути.

## Получить общую ссылку на GitHub Pages

Нужна одна настройка существующего GitHub-репозитория, без сторонних подключений:

1. Откройте **Settings → Pages** в репозитории `Kseniya0512/-change-management-workshop`.
2. **Build and deployment → Source: Deploy from a branch**.
3. **Branch: main**, каталог **/docs**, затем **Save**.
4. Дождитесь успешной встроенной сборки GitHub Pages. Её состояние видно в Actions; подтверждённый адрес появится в Settings → Pages.

После включения новые изменения `docs/index.html` в main будут публиковаться автоматически. GitHub сам обслуживает HTML и HTTPS. В этом сеансе доступ к GitHub REST API и github.io заблокирован сетевой политикой среды (CONNECT 403), поэтому первое включение Pages и фактический публичный адрес не подтверждены агентом. Копия HTML работает независимо от публикации.

## Разработчику

```bash
npm ci
npm run build:offline
npm run test:offline
```

`build:offline` проверяет типы, собирает автономный entry через Vite, встраивает JS/CSS и обновляет готовый `docs/index.html`. Этот файл хранится в Git, поэтому конечному пользователю ничего собирать не требуется. Серверная сборка `npm run build` продолжает использовать собственный `dist`.

Браузерные проверки исполняют HTML в изолированном origin с подставленным содержимым документа и `context.setOffline(true)`: нет доступа к сети или дополнительных ресурсов. Сохранение, перезагрузка, независимые листы, таймер, экспорт/импорт, мобильный экран и недоступное хранилище проверяются в настоящем Chromium. Нативный `file://` в управляемом Chromium этой облачной среды блокируется политикой администратора; его выполнение в этой среде не выдаётся за проверенное.
