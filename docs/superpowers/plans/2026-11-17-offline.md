# Offline Workshop Implementation Plan

**Goal:** один HTML-файл для игры без подключений и публикация в GitHub Pages при доступе.
**Architecture:** общий Stage/Form/model + отдельный OfflineApp/store; Vite-сборка с inline JS/CSS.
**Spec:** docs/superpowers/specs/2026-11-17-offline-design.md.

- [x] Тесты: локальное сохранение, восстановление таймера, изоляция листов, валидация импорта, режим без storage; browser file://, отсутствие HTTP, экспорт и восстановление.
- [x] Реализовать локальное хранилище и OfflineApp, локальные кнопки экспорта плана без /api.
- [x] Добавить воспроизводимую сборку docs/index.html, не затрагивая production dist серверной версии.
- [x] Проверить unit/API, оба build, file:// browser, существующие server browser tests.
- [x] Подготовить main/docs для встроенной публикации GitHub Pages и включить Pages, если доступно; подтвердить URL ответом страницы. Иначе доставить проверенный HTML и точно указать необходимое действие в GitHub.
- [x] Обновить README/deployment и настройки среды, commit/push в main.


Решение о публикации: по официальному action.yml actions/configure-pages/v5 первое включение Pages требует токен с дополнительными правами, отличный от GITHUB_TOKEN. Не добавляем заведомо падающий workflow и не создаём требования нового сервиса/секрета. Сохраняем готовый файл в main/docs: владелец включает Pages в настройках репозитория один раз, затем встроенная публикация работает автоматически. GitHub REST API заблокирован сетевой политикой текущей среды (CONNECT 403); git push работает. Пока это не изменилось, общий адрес не подтверждён.


Итог: 19 unit/API + 6 browser прошли; оба build прошли. Готов docs/index.html. Условие «включить Pages, если доступно» проверено: доступ заблокирован сетевой политикой, указано точное действие владельца в GitHub. Нативный file:// в управляемом браузере также запрещён, HTML проверен без сети с подставленным документом и отдельно как обычная статическая страница. Ни один из этих внешних пунктов не выдан за выполненный.
