# Командный воркшоп: единый корпоративный мессенджер

Основание: README.md, docs/game-spec.md (дополнение имеет приоритет), доступные PDF, HTML и снимок критериев. Презентация «Внедрение изменений в проектах и процессах HR» отсутствует и не изучалась.

## Результат и границы
Один кейс, вводная + семь заданий + финал, 30 минут: 1/2/3/5/5/5/5/3/1. Все пользовательские тексты русские. Нет рейтинга, штрафов или других сценариев. Восемь критериев, порог 2; критерии 5/6/8 допускают уточнение. Сохраняем пять шагов ЦЭИ отдельно от четырёх этапов внедрения.

## Архитектура (выбор исполнителя)
React + TypeScript + Vite; Express на Node.js >=24. SQLite (node:sqlite) на постоянном диске, WAL, транзакции. Один сервер приложения. SSE с HttpOnly-сессиями, повторное подключение и актуальный снимок состояния. Сервер авторизует каждое действие. Версии отдельных полей предотвращают потерю параллельных изменений; конфликт возвращает 409 и актуальные ответы. Браузер не является хранилищем ответов.

Альтернативы: PostgreSQL + внешний realtime удобны для нескольких серверов, но требуют внешних реквизитов; локальное браузерное хранение не выполняет требования. SQLite подходит для 20 участников на одном сервере и не требует облачного провайдера. Несколько реплик требуют переноса БД и шины событий.

## Роли и сеансы
Ведущий создаёт комнату на 2 или 3 команды, получает отдельные секретные приглашения для капитана, помощника и участников каждой команды. Приглашения передаются в URL fragment, обмениваются на серверную сессию и удаляются из адреса. Ведущий управляет общим таймером, видит планы и прогресс всех команд, выдаёт игровое событие. Капитан редактирует ответы и выдаёт право редактирования отдельным участникам. Помощник даёт комментарии; он не является спонсором изменения. Все видят сохранённые ответы своей команды, обсуждают в журнале.

## Интерфейс и задания
Светлый рабочий стол, тёмная боковая навигация, синий акцент, карточки, адаптивность и клавиатурное управление. Статусы сети и сохранения, подсказки ЦЭИ, предупреждения и объяснения после попытки. Вводная содержит проверку первого обращения в ЦЭИ. Семь заданий реализуют сортировку Было/Стало, цель и ступень; критерии; маршрут и встроенный план Б/4 этапа; роли и кандидаты по 5 критериям; группы/потери/3 возражения; перестановку воронки и коммуникационный план/обратную связь; 2 метрики с целями, сроками и источниками. Расширенные поля сгруппированы в раскрываемые блоки, чтобы сохранить темп воркшопа.

Финал содержит 20 разделов из фактических ответов, статусы заполненности и «Требует уточнения» для пропусков; экспорт Markdown, JSON и печать/PDF браузера. Можно вернуться и исправить решение. Никаких придуманных нормативов стабильности.

## Развёртывание
Один Node-процесс раздаёт собранный фронтенд и API. Постоянный том /data для БД, HTTPS через внешний прокси, SSE без буферизации. Dockerfile, пример Compose и инструкция резервирования SQLite. Без внешних API и секретов для базового запуска. Приглашения предоставляют доступ к учебной комнате; это не корпоративный SSO.

## Проверка
Unit: правило 2/8, полнота этапов, 20 разделов, реальные ответы и пропуски. API integration: полномочия, изоляция команд, параллельные изменения, конфликты, таймер, SSE, перезапуск с той же БД, экспорт. Browser: создание комнаты, разные контексты/роли, прохождение и исправление ответов, мобильная вёрстка. Production build и проверка типов.
